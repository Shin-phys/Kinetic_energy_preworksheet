# 力学的エネルギー 立式ドリル

力学的エネルギー保存則の「立式」を反復練習するWebアプリです（仕様は [docs/spec.md](docs/spec.md)）。
問題文と図から、**はじめ**と**あと**に残るエネルギーの項（½mv₀²・mgh₀・½kx₀² ／ ½mv²・mgh・½kx²）をスイッチで選びます。選択肢から式を探すのではなく、**どの項が生き残るかを自分で判断する操作のまま自動採点**します。

- 公開URL（GitHub Pages）：`https://shin-phys.github.io/Kinetic_energy_preworksheet/`
- ビルド不要・外部ライブラリなし（HTML／CSS／JavaScript モジュールのみ）
- 記録は端末の localStorage に保存（サーバ・ログイン不要）

## しくみ

| モード | 記録 | 内容 |
|---|---|---|
| **本番**（青） | 残る | タイムアタック。全問正解するまで終わらない。クリアタイムで称号 |
| **練習**（灰） | 残らない | 時間無制限。1問ごとに解説 |
| **腕試し**（紫） | 残る（別枠） | 初見の基礎問題からランダム10問。本番で「新幹線級」以上を取ると解放 |

- コース：**前半**（No.1〜10）／**後半**（No.11〜20）／**通し**（20問）。No. は配布プリントと同じ。
- 誤答1回目：1.5秒操作できなくなり、**ヒント**（問いかけ）。2回目：**正解を表示**し、自分で入力して次へ。
- 称号：導線中の電子級 → 歩く人級 → … → 光速級（10級）。ノーミスなら ★。**称号図鑑**では未獲得の級名が伏せられ、時間区分だけが見える。獲得した級は速さをタップすると高校物理につながる解説が読める。
- 式の表記：はじめの量は添字 0、あとの量は添字なし（例：`mgh₀ = ½mv² − mgh`）。内部データでは K・U・E の記号で持つ。
- 印刷：問題プリント・解答プリント・記録用紙（A4）をアプリ内から印刷できる。

    session.js          タイムアタックの進行

  patterns.json         ★出題パターン A1〜D1（正答・ヒント・解説）

★ が日常的に編集するファイルです。

## キーボード（PC・タブレット）

| キー | 動作 |
|---|---|
| `1` `2` `3`（`K` `U` `E`） | 選んでいる行の ½mv²・mgh・½kx² を切り替え |
| `4` / `=`（`Tab` `←` `→`） | 【はじめ】【あと】の行を切り替え |
| `Enter` / `Space` | 判定 |
| `0` / `N` | 「保存則は使えない」を選ぶ／外す（そのあと判定） |
| `Backspace` | 選んでいる行を空にする |
| `Esc` | 中断 |

## 教員向け

### リンクで条件を配る

| パラメータ | 値 | 意味 |
|---|---|---|
| `course` | `first` / `second` / `full` | 最初に選ばれているコース |
| `lock` | `1` | コースを固定（生徒が切り替えられない） |
| `warmup` | `1` / `0` | 本番前のウォームアップ |
| `challenge` | `1` | 腕試しを最初から解放 |
| `view` | `print` | 印刷ページを直接開く |

例：`…/Kinetic_energy_preworksheet/?course=first&lock=1`

### 称号の秒数を決める（仕様書 7.2）

`js/config.js` の `TITLE_TIMES` を編集します（10問あたりの秒数。20問は自動で2倍）。

```js
export const TITLE_TIMES = { walk: 120, light: 31 };   // 教員の最速 28秒 ＋ 3秒
```

`light`（光速級）＝「現実的に極めれば届く最速タイム ＋ 3秒」。現在は 31秒（教員の最速 28秒＋3秒）。生徒の記録を見て必要なら見直してください。間の級は等比で自動的に割り振られます。

### 問題を編集する

- 本番20問・腕試しの問題文は `data/questions.json`。`start` `end` `hint` `trap` `diagram` は `data/patterns.json` から継承（問題側に書けば上書き）。
- 図や文には「静かに → v₀=0」「最高点 → v=0」など **言い回しから導く条件を書かない**（仕様書 4.1）。それはヒントで問う。
- 編集後にチェック：

  ```sh
  node tools/validate.mjs     # 構成チェック（No.1〜20、前半・後半の構成、ヒントの有無など）
  npm test                    # ロジックのテスト
  ```

### 記録の集め方（段階的）

1. **localStorage のみ**（既定）：端末内で記録・グラフ・図鑑まで完結。
2. **書き出し**：結果画面の「結果コードをコピー」→ Googleフォームに貼り付け。記録画面から CSV 保存も可。
3. **GAS＋スプレッドシート**：`gas/Code.gs` の冒頭の手順でデプロイし、URL を `js/config.js` の `GAS_ENDPOINT` に設定すると「記録を送信」が現れます。出席番号を設定済みなら本番終了時に自動送信。

記録・称号は振り返りの材料です。評価に直結させない運用を想定しています（仕様書 8.5）。

## ローカルで動かす

JavaScript モジュールと `fetch` を使うため、`index.html` をダブルクリックで開くと動きません。

```sh
python3 -m http.server 8000   # → http://localhost:8000/
```

## GitHub Pages で公開

リポジトリの Settings → Pages → Branch: `main` / `(root)` を選んで保存。
